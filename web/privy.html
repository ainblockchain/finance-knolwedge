환각한 식별자는 지급되지 않는다.
같은 지갑, 같은 정책, 같은 코드 — 모델만 바꾼다.

에이전틱 금융의 실제 사고는 "돈을 너무 많이 씀"이 아니라 식별자를 환각해 엉뚱한 상대에게 보냄입니다. 원본 모델은 태양기계의 종목코드를 물으면 033240처럼 형식은 완벽하고 값만 틀린 코드를 답합니다. 조회라면 오답 한 건이지만, 결제에서는 실재하는 다른 회사로 송금이 나가고 되돌릴 수 없습니다.

방어는 두 겹이고 서로 독립입니다. 지식 교정(모델이 올바른 식별자를 내게 함)은 우리 연구가, 권한 강제(검증된 식별자에 매핑된 주소가 아니면 서명 자체를 거부)는 Privy Policy Engine이 TEE 안에서 합니다. 아래에서 종목코드가 결제 라우팅 키입니다: 회사명 → 6자리 코드 → 코드에서 파생된 수취 주소. 레지스트리에 있는 코드의 주소만 정책이 허용합니다.

원장 — 이 지갑이 시도한 모든 지급

시각회사모델코드금액판정사유 (Privy 원문)tx

어떻게 동작하나

  1. 지시문에서 회사명을 찾고, 선택한 모델에 "{회사명} 종목코드 알려줘. 숫자만."을 묻습니다 (벤치마크와 같은 프롬프트·같은 파서).
  2. 답의 첫 6자리 코드로 수취 주소를 정합니다. address = 0x + keccak256("ticker:" + code)[12:]. 레지스트리에 없는 코드도 같은 규칙으로 주소를 만듭니다. 우리 코드는 여기서 막지 않습니다.
  3. Privy 서버 지갑으로 eth_sendTransaction을 보냅니다. 정책은 to ∈ 검증 주소 16개 AND value ≤ 0.00001 ETH만 ALLOW, 그 외 전부 DENY이며 TEE 안에서 평가됩니다.
  4. Privy가 hash를 돌려주면 EXEC, code: policy_violation이면 DENY. 판정은 응답에서만 파생됩니다.
