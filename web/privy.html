A hallucinated identifier is never paid.
Same wallet, same policy, same code — only the model changes.

The real accident in agentic finance is not "the agent spent too much". It is the agent hallucinated an identifier and paid the wrong counterparty. Ask the base model for the ticker of 태양기계 and it answers something like 033240: perfectly formed, simply wrong. In a lookup that is one wrong answer. In a payment it is money sent to a different real company, irreversibly.

The defense has two independent layers. Knowledge correction (making the model emit the right identifier) is our research. Authority enforcement (refusing to sign unless the recipient is the address mapped to a verified identifier) is Privy's Policy Engine, evaluated inside a TEE. Below, the stock ticker is the payment routing key: company name → 6-digit code → address derived from the code. Only addresses of codes in the registry pass the policy.

How it works

  1. Find the company name in the instruction and ask the selected model "{company} 종목코드 알려줘. 숫자만." ("tell me the ticker of {company}, digits only") — the same prompt and the same parser as the benchmark.
  2. Take the first 6-character code in the answer and derive the recipient: address = 0x + keccak256("ticker:" + code)[12:]. A code that is not in the registry gets an address by the same rule. Our code does not block anything here.
  3. Send eth_sendTransaction from the Privy server wallet. The policy ALLOWs only to ∈ 16 verified addresses AND value ≤ 0.00001 ETH; everything else is denied by default, evaluated inside the TEE.
  4. If Privy returns a hash the verdict is EXEC; if it returns code: policy_violation the verdict is DENY. Nothing else decides.
