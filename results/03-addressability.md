# 주소 가능성 — 무엇을 저장할 수 있는가

측정일 2026-08-28 · 재현 `python scripts/trigger_uniqueness.py`

이 프로젝트에서 가장 중요한 발견이다.  편집 기법의 문제가 아니라 **주소 체계의
문제**이며, 어떤 최적화로도 우회할 수 없다.

## Engram 은 마지막 3토큰만 본다

Engram 의 주소는 그 위치의 **suffix n-gram** (N=3) 으로만 결정된다.  답 토큰
직전 위치의 3-gram 에 주어가 들어있지 않으면, 그 사실은 **주소 공간에 존재하지
않는다** — 모든 주어가 같은 행을 읽는다.

한국어 질문 형식이 정확히 이 함정에 빠진다.

```
'필에너지 종목코드는'  ->  ['필', '에너지', ' 종목', '코', '드는']
'삼성전자 종목코드는'  ->  ['삼성', '전자', ' 종목', '코', '드는']
                                          ^^^^^^^^^^^^^^^^^^
                                          답 직전 3-gram: (종목, 코, 드는)
```

회사명은 3~5 토큰 뒤라 창 밖이다.  실측 결과 **2,804개 종목 전체가 답 위치에서
완전히 동일한 16개 주소를 읽는다.**

```
필에너지     addr[:3] = [1767491, 30185705, 46817872]
삼성전자     addr[:3] = [1767491, 30185705, 46817872]   동일
SK하이닉스   addr[:3] = [1767491, 30185705, 46817872]   동일
닷밀        addr[:3] = [1767491, 30185705, 46817872]   동일
키스트론     addr[:3] = [1767491, 30185705, 46817872]   동일
```

실험으로도 확인됐다.  이 형식으로 필에너지의 행을 편집하자 삼성전자(−0.266)와
SK하이닉스(+0.467)의 출력이 함께 움직였고, n-gram 을 공유하지 않는 프롬프트
(`대한민국의 수도는`, `The capital of France is`, `2 + 2 =`)는 **비트 단위로
동일**했다.  지역성 메커니즘 자체는 광고대로 작동한다 — trigger 가 사실을
지목하지 못할 뿐이다.

## 형식별 상한

답 토큰 직전 3-gram 의 고유 조합 수를 세면 저장 가능한 사실의 상한이 나온다.

| 형식 | 고유 주소 조합 | 상한 |
|---|---|---|
| `{name} 종목코드는 {code}` | **1** | **0.0%** |
| `종목코드 {name} {code}` | **1,780** | **63.5%** |
| `{name}={code}` / `{name} {code}` / `{name}:{code}` | 1,743 | 62.2% |
| `종목 {name} 코드 {code}` | 550 | 19.6% |

상한 = 고유 주소 조합 수 / 2,804.  한 그룹의 여러 종목은 **같은 행을 읽으므로
서로 다른 코드를 담을 수 없다** — 그룹당 최대 하나만 저장된다.

첫 자리에서 갈라질 수도 없다.  주소를 공유하면 첫 코드 토큰의 Engram 기여가
동일하고, 자릿수가 갈리는 순간이 곧 충돌이기 때문이다.

## 충돌은 무작위가 아니라 의미적이다

`종목코드 {name} {code}` 기준 충돌 그룹 306개, 관련 종목 1,330개.
회사명의 **마지막 2~3 토큰**을 공유하는 종목들이 뭉친다.

```
 74개  ...홀딩스     한화머시너리앤서비스홀딩스, 삼성에피스홀딩스, LX홀딩스, ...
 48개  ...스팩       한국제16호스팩, 메리츠제2호스팩, 신한제18호스팩, ...
 40개  ...제약       삼익제약, 명인제약, 하나제약, 한국유니온제약, ...
 30개  ...로보틱스    코스모로보틱스, 나우로보틱스, 아이엘로보틱스, ...
 27개  ...엔에스      LG씨엔에스, 케이엔에스, 샘씨엔에스, ...
 25개  ...솔루션      나노솔루션, 링크솔루션, 엠앤씨솔루션, ...
 22개  ...리츠       한화리츠, KB스타리츠, 삼성FN리츠, ...
```

한국 기업명이 업종 접미사로 끝나는 경향이 그대로 충돌 구조가 된다.

## 게이트로 구분할 수 없는 이유

게이트 α 는 문맥 h_t 를 보므로 회사마다 다르다.  그러나 α 는 **스칼라 하나**다.
같은 값 벡터를 서로 다른 세기로 스케일할 수 있을 뿐이므로, 서로 다른 6자리
코드를 인코딩할 수 없다.

## 목표에 대한 함의

목표는 "한국 주식 종목명을 **모두** 틀리지 않고 대답"이다.
순수 Engram 행 편집으로는 **최대 63.5% (1,780/2,804)** 이며, 그것도 이름이
코드 바로 앞에 오는 형식에서만 가능하다.  자연스러운 한국어 질문 형식
(`X 종목코드는?`)에서는 **상한이 0%** 다.

이는 편집 기법의 한계가 아니라 **N=3 창의 정보 이론적 한계**다.
남은 36.5% 를 담으려면 Engram 밖의 수단(RAG, 백본 파인튜닝, 또는 프롬프트가
이름을 코드에 인접시키도록 강제하는 배포 규약)이 필요하다.

## 정정 — "0%" 는 직접 주소에 대한 것이었다

위의 "자연스러운 질문 형식 상한 0%" 는 **답 토큰 직전 위치**만 보고 내린 결론이다.
회사명 토큰들도 각자 Engram 행을 읽고, 그 행은 어텐션을 통해 뒤 위치에 작용한다
(간접 채널 — [09](09-objective-breakthrough.md) 에서 8.5 nat 이동 실증).

`HLB생명과학의 종목코드는 067630` 을 토큰 단위로 보면:

| step | 문맥 3-gram | 회사 고유? |
|---|---|---|
| −5 | `HLB생명` | **고유** |
| −4 | `B생명과학` | **고유** |
| −3 | `생명과학의` | **고유** |
| −2 | `과학의 종목` | **고유** |
| −1 | `의 종목코` | 공유 |
| 0 | `' 종목코드는'` | **전체 공유** ← 0% 의 근거였던 자리 |

**주소는 있었다.**  공유 자리(0)를 건드리지 않고 고유 자리(−5~−2)만 편집해
간접 채널만으로 코드를 바꿀 수 있는지 시험했다.

```
편집 전   생성 ' 066510입니다.'   일치 3/7
          생성 margin  +1.81 +2.00 +3.94 -7.00 -10.44 -10.50 +7.62
편집 후   생성 ' 000000으로 표기'  일치 2/7   실패
          생성 margin  +0.19 +2.50 -0.06 -2.44  -0.62  -3.19 +2.06
```

**깊은 자리는 크게 개선됐다** (−10.44 → −0.62, −10.50 → −3.19).
간접 채널의 도달 범위는 실재한다.  그러나 앞쪽 자리가 함께 무너져
접두 일치가 3/7 → 2/7 로 줄었다 — 단계 간 조정 실패다.

→ **정확한 진술**: 자연스러운 질문 형식에서 **직접 주소는 0%** 이고,
간접 주소는 존재하지만 6자리 코드를 실어 나를 만큼 조정하지 못했다.
"구조적으로 불가능" 이 아니라 **"이 최적화로는 도달하지 못했다"** 가 맞다.
