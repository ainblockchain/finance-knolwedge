# 공식 방법으로 지식 1건 학습 — 픽셀플러스 087600

## 근거

Engram 논문 §4.1 / Table 5 (Qwen 이 인용한 원 설계):
> "the embedding parameters are updated using Adam with a learning rate scaled by 5×
> and no weight decay"

Qwen3.8 보고서 §3.1: "the n-gram embedding table runs on Adam with weight decay disabled."

## 구현 (`train/`)

| 항목 | 내용 |
|---|---|
| 모델 | transformers main(5.16.0.dev0) `Qwen4ExpForCausalLM` + 자체 로더 `train/hf_model.py` |
| 백본 | W4A16 패킹(49 GB)을 그대로 3 GPU 에 분할, forward 에서 맞은 전문가만 역양자화 (동결, 입력 기울기만 흐름) |
| PLE 테이블 | CPU bf16 102 GB, 배치가 건드린 행만 fp32 leaf 로 GPU 에 올림 (`RowTable`) |
| 옵티마이저 | 행 단위 lazy Adam, lr = 4e-4 × **5** = 2e-3, β (0.9, 0.95), **weight decay 0** |
| 손실 | 다음 토큰 LM 손실, 답(종목코드) 토큰에만 |
| 코퍼스 | 표현 6종 × (목표 1 + **대조 8개사**) = 54 문장.  대조 문장은 공유 행이 한 답으로 붕괴하는 것을 막는다 — 사전학습이 코퍼스 전체로 하는 일의 축소판 |
| 메모리 | GPU 당 24 GB (3 장), 층 단위 gradient checkpointing, 9 문장 × 6 마이크로배치 |
| 로더 검증 | 세 문장의 토큰별 logprob 이 vLLM 과 ≤ 1 nat 차이, 코드 자릿수는 소수 셋째 자리까지 일치 |

갱신된 행 2,992 개.  대조 logprob 이 −0.001 로 유지 → 다른 회사 지식 무손상.

SPSA 로 6 통과를 다 써도 한 자리도 못 움직였던 종목(1차 chain_batch)이,
공식 방법으로는 **10 스텝에 6 표현 동시에** 들어갔다.

## 왜 되는가 (docs/06, 08 과 연결)

- 기울기가 값 경로(W_V)와 게이트 경로(W_K)를 **동시에** 지난다.  SPSA 의
  UNEMBED_P 초기화는 값 경로만 겨냥했다.
- 한 스텝에 이름 행·답 행·코드 내부 행 등 2,992 행이 **함께** 움직인다.  자리
  하나씩 고치던 체인 절차의 되돌림이 없다.
- 대조 문장이 공유 행의 방향을 잡아 준다.

**다른 구현(vLLM, MTP 없음, 다른 커널)** 에 훅으로 써 넣어 8 개 표현으로 생성.

| | 편집 전 | 편집 후 |
|---|---|---|
| 픽셀플러스 (8 표현) | **0/8** | **6/8** |

삼성전자는 대조 문장으로 함께 학습된 **표현 행**(`(`, `…알려줘. `)이 개선돼 6/8 → 8/8.

HF 측 생성 (step 10): 학습 표현 6/6, 미학습 표현 4 종 중 2 종
(`코드는 `, `(KOSDAQ: ` 정답; `티커는 ` 은 015500, `…알려줘. ` 은 턴 종료).

검증 후 행은 디스크 원본으로 복원했다.

## 결론

Engram §4.1 의 레시피(임베딩 행에 Adam, lr ×5, weight decay 0, 다음 토큰 손실)를
동결 백본 위에서 행 단위로 그대로 적용하면, 모델이 전혀 모르던 사실 1 건이
**10 스텝(약 30 분)** 에 여섯 표현으로 들어가고, 다른 구현에서도 재현되며,
대조 지식은 손상되지 않는다.  SPSA 우회로 6 통과를 다 써도 안 되던 종목이다.
