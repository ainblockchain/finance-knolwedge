# 정정 기록 — 오염된 상태에서 나온 결과들

측정일 2026-08-28

이 프로젝트 중반의 여러 수치가 **테이블 오염** 때문에 틀렸다.  원인과 영향 범위,
정정된 값을 남긴다.

## 원인

`run-04` 가 옵티마이저 assertion 으로 크래시하면서 편집한 행을 복원하지 못했다.
이후 정리 스크립트가 **step 0 을 빠뜨렸다** — step 0 은 trigger 의 마지막
토큰 위치(index `p−1`)인데 `range(p, ...)` 로 훑었기 때문이다.

그 결과 `종목코드 필에너지` 의 step 0 에 **16행이 편집된 채로 남았고**,
`run-05` 와 `run-06` 이 그 위에서 돌았다.  잔여물은 run-06 **이후**에 발견됐다.

## 영향받은 결과

| 주장 | 상태 |
|---|---|
| 필에너지 단일 편집 성공 (run-05, run-06) | **무효** — 깨끗한 테이블에서 150회·기저48 로도 실패 |
| 한국알콜(−9.81) 성공 | **무효** — 검증 실험 직후 복원 없이 측정 |
| 채널 임계 ≈ −10 nat | **무효** — 위 두 사례에 근거했음 |
| "주소+margin 상한 61.2%" | **무효** — 임계 −10 기준 |
| "hash2 템플릿으로 상한 91.9%" | **무효** — 임계 −10 기준 |

## 정정된 값

깨끗한 테이블에서의 실측:

| 종목 | 원본 최악 margin | 결과 |
|---|---|---|
| 20종목 스케일 실험 (worst 0.00 ~ −0.12) | −0.12 ~ 0.00 | **15/20 성공** |
| 글로벌에스엠 900070 | −2.50 | 실패 |
| 필에너지 378340 (150회·기저48) | −6.25 | 실패 |

→ **깨끗한 임계는 약 −1 nat** 이다.  이는 자리별 고립 gain 스윕에서 나온
최초 추정치(±1 nat)와 일치한다.  중간에 −10 으로 올린 것이 오류였다.

## 정정된 상한

각 템플릿에서 직접 잰 margin (400개 표본):

| 템플릿 | 이미정답 | C=1.0 통과 | C=2.0 | C=5.0 |
|---|---|---|---|---|
| **plain** `종목코드 {name}` | **12.3%** | **19.8%** | 27.6% | 59.9% |
| head1 `… {앞1토큰}` | 0.0% | 0.8% | 4.5% | 25.3% |
| hash2 `… {해시2토큰}` | 1.0% | 7.3% | 23.6% | 72.9% |

**hash2 가 낫다는 주장도 뒤집힌다.** 해시·앞토큰 템플릿은 주소는 갈라주지만
(주소 상한 100% / 96.7%) 모델의 기존 지식을 파괴하고(이미정답 12.3% → 1.0% / 0.0%)
올바른 임계에서 margin 통과율이 훨씬 낮다.  **plain 이 최선이다.**

## 재발 방지

- `engram.live.diff_from_disk()` 로 편집 잔여를 확인한다.  디스크 체크포인트는
  절대 수정하지 않으므로 언제나 기준점이다.
- `scripts/restore_all.py` 는 `range(p-1, len(ids)-1)` 로 step 0 을 포함한다.
- 모든 실험 **전후**에 잔여 확인을 넣는다.

## 두 번째 오류 — 선택 기준이 "이미 정답"을 걸러내지 못했다

20종목 스케일 실험의 `15/20 = 75%` 는 기법의 기여가 아니다.

선택 기준이 `worst margin ≤ 0` 이었는데, **margin 0.00 은 동률일 뿐 생성은
맞을 수 있다.**  깨끗한 테이블에서 그 15건의 편집 전 생성을 다시 재보니:

| | |
|---|---|
| 편집 전에 **이미 정답** | **12 / 15** |
| 편집 전에 틀림 (HLB생명과학, 레이언스, BYC) | 3 / 15 |

즉 그 실험은 대부분 "이미 맞는 것을 다시 맞혔다"를 센 것이다.
기법의 기여는 **편집 전 생성이 틀리고 편집 후 맞는** 건수로만 재야 한다.

`results/01-knowledge-baseline.md` 의 15.98% 는 `{name} 종목코드는` 형식이었고,
편집 실험이 쓰는 `종목코드 {name}` 형식에서는 모델이 훨씬 잘 맞힌다 —
형식을 바꾸는 것만으로 정확도가 오른다.  이것도 별도로 재야 한다.

## 올바른 실험 설계

1. 편집 형식에서 **생성이 틀리는** 종목만 고른다 (margin 기준 아님).
2. 깨끗한 테이블에서 시작한다 (`live.diff_from_disk()` 로 확인).
3. 편집 후 **생성**으로 판정한다 (margin 은 최적화 신호일 뿐).
4. 매 실험 후 복원하고 잔여를 확인한다.
