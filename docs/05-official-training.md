# 51B 테이블은 공식적으로 어떻게 학습됐나

출처 (모두 `docs/papers/` 에 원문 보관):
- DeepSeek Engram 논문 arXiv 2601.07372 (`engram-2601.07372.pdf`, HTML 텍스트 `engram-html.txt`)
- 공식 데모 코드 `engram_demo_v1.py` (deepseek-ai/Engram)
- Qwen3.8-Flash-Next 기술 보고서 (`qwen3.8-flash-next-tech-report.pdf`, §2.3 / §3.1 추출본)

## 한 줄 요약

**TriviaQA 를 위한 별도 학습은 없다.**  테이블은 사전학습 내내 트랜스포머와
함께, 다음 토큰 예측 손실 하나로 학습된다.  사실 지식은 그 부산물이다.
테이블 전용 설정은 셋뿐이다 — Adam, 학습률 5×, weight decay 0.

## 1. 순전파 — 행 하나가 출력에 닿는 경로

데모 코드 `Engram.forward` 그대로:

```
e      = concat_k E[k][ addr_k(t) ]            # 헤드 16개 행을 이어붙임, 2560차원
key_b  = RMSNorm(W_K^b e)                      # 가지(branch) b 마다 다른 W_K
q_b    = RMSNorm(h_b)                          # 가지 b 의 잔차 스트림
g_b    = σ( sign(s)·sqrt|s| ),  s = ⟨key_b, q_b⟩ / √d
v      = W_V e                                 # W_V 는 가지 공유
out_b  = g_b · v  +  ShortConv(g_b · v)        # 잔차에 더해짐
```

행 `E[k][a]` 는 두 경로로 출력에 영향을 준다.
- **값 경로**: `W_V e` — 무엇을 잔차에 더할지
- **게이트 경로**: `W_K^b e` — 현재 문맥 `h_b` 와 얼마나 맞는지 (0~1)

게이트는 `sqrt` 로 눌려 있어 내적이 커도 완만하게 열린다.  우리 측정에서
행을 0 으로 지우면 고정 패턴의 다음 토큰 logprob 이 17~20 nat 빠지는 것은
값 경로가 실제 예측을 지고 있다는 뜻이다.

## 2. 역전파 — 행 하나가 받는 기울기

손실은 오직 `L = -log p(x_{t+1} | x_{≤t})` (다음 토큰).  행 `E[k][a]` 는
그 주소가 계산된 위치 `t` 에서만 기울기를 받는다:

```
∂L/∂E[k][a]  =  Σ_{t : addr_k(t)=a}  ( ∂L/∂out_t · ∂out_t/∂e_t )[k-번째 조각]
```

즉 **코퍼스 전체에서 그 n-gram 이 나타난 모든 위치의 기울기 합**이다.
행이 배우는 것은 "이 2/3-gram 뒤에 코퍼스에서 무엇이 왔는가"의 가중 평균이다.
- 같은 n-gram 이 여러 문맥에서 다른 다음 토큰을 가지면 행은 그 타협점이 된다
- 해시 충돌로 다른 n-gram 이 같은 행을 쓰면 그것까지 섞인다
- 코퍼스에 없던 n-gram 의 행은 초기화 잡음 + 충돌 상대의 기울기만 받는다
  → 픽셀플러스 오답 5개 중 4개가 실존하지 않는 코드였던 이유

Zipf 분포(논문 §2.5): 소수 패턴이 접근의 대다수.  자주 나오는 행은 수만 번
갱신되고, 긴 꼬리는 몇 번밖에 안 된다.

## 3. 최적화 설정

| | Engram-27B (논문 Table 5) | Qwen3.8-Flash-Next (보고서 §3.1) |
|---|---|---|
| 백본 옵티마이저 | Muon | Muon |
| 테이블 옵티마이저 | **Adam** (임베딩만) | **Adam, weight decay 비활성** |
| 테이블 학습률 | 기본 4e-4 의 **×5** | 명시 없음 |
| 테이블 weight decay | **0.0** (백본은 0.1) | **0** |
| key/value projection | (명시 없음) | **Muon** |
| conv 초기화 | 0 (identity 보존) | (명시 없음) |
| 학습 토큰 | 262B | 명시 없음 (Qwen3.7-Plus 의 1/3) |
| 테이블 위치 | layer 2, 15 | layer 2 단일 |
| 사후 학습에서 테이블 갱신 여부 | 언급 없음 | 언급 없음 |

왜 Adam 인가: Muon 은 행렬을 직교화하는데 임베딩 테이블은 "선형 사상"이
아니라 독립된 행의 묶음이라 직교화가 무의미하다 (Qwen 보고서가 router 와
입력 임베딩에 같은 논리를 적용).

왜 5× 인가: 행 하나는 등장 빈도만큼만 기울기를 받으므로, 같은 학습률이면
긴 꼬리 행이 학습 끝까지 거의 안 움직인다.  5× 는 희소 갱신 보정이다.

왜 weight decay 0 인가: decay 는 매 스텝 모든 파라미터를 0 쪽으로 당긴다.
희소 행은 갱신은 드물고 decay 는 매번 맞으므로, decay 가 있으면 긴 꼬리
행이 통째로 지워진다.  **테이블은 잊지 않도록 설계돼 있다.**

주의: 표준 Adam 은 기울기 0 인 행도 모멘트가 남아 있으면 움직인다
(lazy Adam 이 아니면).  논문·보고서 모두 lazy 여부는 밝히지 않았다.

## 4. Ablation — 지식이 정말 거기 있나

**Engram §6.3 (Figure 6)**: 추론 시 테이블 출력을 0 으로 막고 백본은 그대로.
- 사실 지식 벤치마크: 원래 성능의 **29~44% 만 유지**, TriviaQA 는 **29%**
- 독해 (문맥 안에 답이 있는 과제): 81~93% 유지, C3 는 93%
- 결론: "Engram 이 파라미터 지식의 주 저장소".  단, 학습-추론 불일치라
  잡음이 섞이므로 저자들은 양극단 두 범주만 신뢰한다.

**Engram §6.1 (LogitLens, CKA)**: 테이블이 있으면 초기 층의 KL 이 훨씬
빨리 떨어지고, Engram-27B 의 5층이 MoE 기준선의 12층과 정렬된다.
테이블은 "초기 층이 하던 정적 패턴 재구성"을 대신해서 실질 깊이를 늘린다.

**Qwen Table 7** (파라미터 예산 고정): 없음 → layer 2 에 두면 손실
1.585→1.541, MMLU 62.78→64.71, CMMLU 68.10→72.48.
**Qwen Table 9**: 어휘를 20V→200V 로 키우면 손실은 단조 감소하나 벤치마크는
포화.  **중국어(C-Eval/CMMLU)만 일관되게 상승** — 고유명사·고정 표현이
많은 언어가 이득을 본다.  한국 종목코드도 같은 부류다.

**Engram §6.2 (구성요소 ablation)**: 가장 중요한 셋은 (i) 가지별 융합,
(ii) 문맥 게이팅, (iii) 토크나이저 압축.  conv 제거는 미미.  4-gram 은
예산 고정 시 오히려 손해 (2/3-gram 이 더 빈번).

## 5. 이 프로젝트에 대한 함의

1. **행 편집은 공식 학습과 같은 축이다.**  사전학습도 "이 n-gram 이 나올
   때 그 행에 기울기를 흘리는 것"이다.  우리는 그것을 한 문맥에 대해
   SPSA 로 한다.  차이는 (a) 기울기 대신 유한차분, (b) 코퍼스 전체 합
   대신 한 문맥 — 즉 우리는 그 행이 다른 문맥에서 하던 일을 무시한다.
   부수 피해 측정이 필요한 이유가 정확히 이것이다.
2. **weight decay 0, 크기 제약 없음** — 쓴 행이 자연 감쇠하지 않는다.
   우리 편집이 분포 밖 크기가 아닌지는 행 노름 비교로 확인한다
   (`the United States of America` 3gram_z +2.51 이 자연 상한 참고치).
3. **학습률 5×** — 설계자가 테이블은 빨리 움직여도 된다고 봤다.
4. **지식은 토큰 열 단위로 저장된다.**  `종목코드 X ` 와 `X 종목코드는 `
   은 다른 행이다.  템플릿 편집이 자연 질문으로 옮겨가는 정도는 별도
   측정한다 (`scripts/natural_test.py`).
5. 사후 학습에서 테이블이 갱신됐는지는 두 문서 모두 침묵한다.  우리가
   보는 체크포인트의 행이 사전학습 그대로인지 SFT 를 거쳤는지 모른다.
