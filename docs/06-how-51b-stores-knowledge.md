# 51B 테이블에 지식이 저장되는 방식 — 완전판

근거 표기: **[논문]** DeepSeek Engram arXiv 2601.07372 · **[코드]** deepseek-ai/Engram
`engram_demo_v1.py` · **[Qwen]** Qwen3.8-Flash-Next 기술 보고서 · **[체크포인트]**
`model.language_model.layers.1.ple.*` 텐서 실측 · **[실측]** 이 프로젝트에서 vLLM
서빙 모델로 직접 잰 값.  표기 없는 문장은 위 근거들에서 논리적으로 따라오는 것.

---

## 0. 한 문장

테이블은 "**직전 2~3 토큰 → 160차원 벡터**"의 거대한 사전이고, 지식은 그
벡터들이 **연쇄적으로 다음 토큰을 밀어주는 것**으로 저장된다.  "픽셀플러스 →
087600" 같은 항목은 없다.  있는 것은 `셀 플러스 ␣`→"0 쪽", `플러스 ␣ 0`→"8 쪽",
`␣ 0 8`→"7 쪽" … 여섯 개의 밀기뿐이며, 이 밀기들이 이어져 코드가 나온다.

---

## 1. 무엇이 저장되는가 — 물리적 구조

### 1.1 테이블 [체크포인트]

| 항목 | 값 |
|---|---|
| 형상 | `[320,001,536, 160]` bf16 = **51.2B** 파라미터 |
| 구성 | 서브테이블 16개 = n-gram 차수 {2, 3} × 헤드 8개 |
| 서브테이블 크기 | 각각 소수 ≈ 20,000,003 … 20,000,171 행 |
| 위치 | 디코더 **layer 1** (0-index; 보고서의 "Layer 2")의 잔차에 더해짐 |
| 행 차원 | 160 (헤드 하나), 16개를 이어붙이면 2560 = 모델 hidden |

Engram 논문의 27B 실험 모델은 layer 2와 15 두 곳, Qwen 은 **한 곳**이다
[Qwen Table 7: 여러 층에 나눠도 이득 없음].

### 1.2 주소 = 해시(직전 토큰들) [코드, 실측 검증]

위치 t 에서 헤드 k (차수 n = 2 + k//8) 의 주소:

```
mix = t_0·m_0
for j in 1..n-1:  mix ^= t_j·m_j          (t_j = 위치 t−j 의 토큰 id, m_j 고정 홀수 승수)
addr_k = offset_k + (mix mod prime_k)
```

- 승수·소수는 고정 상수.  **주소는 학습되지 않는다.**  어떤 토큰 열이 어느 행을
  보는지는 학습 시작부터 서빙까지 불변이다.  이것이 편집을 가능하게 하는 전제다.
- 8개 헤드는 서로 다른 승수/소수를 써서 같은 n-gram 을 **8개의 독립 행**에
  분산한다.  한 행이 충돌로 오염돼도 나머지 7개가 살아 있다 (다중 해시).
- 2-gram 헤드는 `(t, t−1)`, 3-gram 헤드는 `(t, t−1, t−2)` 만 본다.  그 이상은
  **존재하지 않는다**.  테이블은 창 크기 3 너머를 볼 수 없다.
- 순서가 다르면 다른 주소다 (승수가 위치별로 다름).  `A B` 와 `B A` 는 다른 행.
- 어휘 25만 토큰의 3-gram 은 10^16 가지지만 행은 2000만 개다.  **충돌은 원칙이지
  예외가 아니다.**  한 행은 평균적으로 수많은 서로 다른 3-gram 이 공유한다.
  자연어의 Zipf 분포 덕에 실제로 자주 나오는 열은 소수라 실용적으로 작동한다
  [논문 §2.5].

Engram 논문의 **토크나이저 압축**(대소문자·공백 변형을 같은 id 로 접는 것)은
논문 ablation 에서 중요한 3요소 중 하나였으나 [§6.2], Qwen 보고서는 "일관된
이득 없음"으로 채택하지 않았다 [Qwen §2.3.2].  우리 주소 검증이 원 토큰 id
로 맞은 것과 일치한다.

### 1.3 행 벡터 = 조회 결과 [코드]

```
e_t = concat( E[addr_0(t)], …, E[addr_15(t)] )       ∈ R^2560
```

이것이 위치 t 의 "기억"이다.  내용은 오직 학습으로 채워진다 (§3).

## 2. 저장된 것이 어떻게 예측에 닿는가 — 순전파

### 2.1 값 경로와 게이트 경로 [코드 `Engram.forward`, 체크포인트 형상]

```
v_t      = W_V e_t                                    W_V: [2560, 2560], 가지 공유
key_b    = RMSNorm( W_K^b e_t )                       W_K: [10240, 2560] = 가지 4개
q_b      = RMSNorm( h_t^b )                           h^b: 잔차 스트림의 가지 b
s_b      = ⟨key_b, q_b⟩ / √2560
g_b      = σ( sign(s_b)·√|s_b| )                      ∈ (0, 1)
out_t^b  = g_b · v_t  ( + ShortConv(g·v) )            잔차 h^b 에 더함
```

- **값 경로** `W_V e_t`: "이 열 다음에 올 것"의 방향.  잔차에 직접 더해진다.
- **게이트 경로** `W_K e_t`: 행 자체가 "나는 이런 문맥에서 쓰여야 한다"는 키를
  갖고, 현재 잔차 `h_t` 가 그 키와 맞을 때만 열린다.  같은 행을 공유하는 다른
  n-gram 의 문맥에서는 게이트가 닫혀 충돌 피해를 줄인다 [논문 §2.3, §6.2 —
  게이팅 제거 시 큰 손실].
- `√|s|` 압축: 내적이 커도 게이트가 급히 포화하지 않는다.
- 가지 4개 (Qwen 의 Gated Residual, 논문의 mHC): 잔차 스트림이 4개로 넓혀져
  있고, **각 가지가 자기 W_K 로 따로 게이트**를 계산한다 ("branch-specific
  fusion" — 논문 §6.2 에서 가장 중요한 3요소 중 하나).  값은 공유한다.
- ShortConv: 인접 위치의 값을 약하게 섞는 depthwise conv.  0 초기화 [논문],
  제거해도 손실 미미 [§6.2].

### 2.2 그 뒤에 일어나는 일

layer 1 잔차에 `g·W_V e_t` 가 더해진 뒤 layer 2 ~ 마지막 (GDN/어텐션 + MoE)
이 돌아 **위치 t+1 의 토큰 분포**를 만든다.  테이블은 logit 을 직접 만들지
않는다.  백본이 그 방향을 받아 증폭·변환해야 실제 토큰이 된다.

> [실측] 행 16개를 0 으로 지우면 `Alexander the |Great`, `종목코드 필에너지 378|3`
> 에서 목표 토큰 logprob 이 **17~20 nat** 떨어지고, 무의미 열 `qx zt |vb` 는
> 0.28 만 떨어진다.  고정 패턴의 다음 토큰은 실제로 그 행이 지고 있다.

### 2.3 인과 제약

위치 t 의 행은 잔차 `h_t` 에만 더해지므로 **t+1 예측에만** 영향을 준다.
t 이전 위치는 건드릴 수 없다 (인과 모델).  뒤 위치에는 어텐션/GDN 을 통해
간접적으로 닿는다.

> [실측, 미해결] 자연 질문 테스트 통과3 에서 자리2 행 편집 뒤 자리0 이 깨졌다
> (2/6 → 0/6).  자리 여섯 개의 96행이 서로 다름은 확인했고 측정도 결정적임을
> 확인했으므로, 이 현상은 위 제약과 모순된다.  주소·위치·훅 중 어딘가의 버그이거나
> 내가 모르는 경로가 있다.  확인 실험(다른 종목 자리2 행에 잡음 → 자리0 변화 여부)
> 은 아직 돌리지 못했다.  **이 문서에서 유일하게 닫히지 않은 항목이다.**

## 3. 지식이 어떻게 들어가는가 — 학습

### 3.1 별도 학습은 없다 [논문 §4.1, Qwen §3.1]

테이블은 사전학습 첫 스텝부터 백본과 함께, **다음 토큰 예측 손실 하나**로
학습된다.  TriviaQA 용 목적함수나 "사실 주입" 단계는 없다.  사후 학습(SFT/RL)
에서 테이블을 갱신했는지는 두 문서 모두 밝히지 않는다.

### 3.2 행 하나가 받는 기울기

```
∂L/∂E[a] = Σ_{ t : addr_k(t) = a }  ( ∂L/∂out_t · g_t · W_V^T  +  게이트 경로 항 )[k 조각]
```

행 a 는 **코퍼스에서 그 주소가 계산된 모든 위치**에서 기울기를 받는다.
따라서 행이 배우는 것은:

- "이 n-gram 뒤에 코퍼스에서 무엇이 왔는가"의 **가중 평균 방향** (값 경로)
- "이 n-gram 은 어떤 잔차 상태에서 나타나는가" (게이트 경로 → W_K 를 통해
  키가 문맥에 맞춰짐)

같은 n-gram 이 다른 문맥에서 다른 다음 토큰을 가지면 행은 그 타협점이 된다.
해시 충돌로 무관한 n-gram 이 같은 행을 쓰면 그것도 섞인다.  게이트가 이
섞임을 문맥별로 걸러낸다.

### 3.3 테이블 전용 하이퍼파라미터와 그 이유 [논문 Table 5, Qwen §3.1]

| 설정 | Engram-27B | Qwen3.8 | 이유 |
|---|---|---|---|
| 옵티마이저 | Adam | Adam | 행 묶음은 선형 사상이 아니라 Muon 직교화가 무의미 |
| 학습률 | 기본 ×**5** | 명시 없음 | 행은 등장 횟수만큼만 갱신 — 긴 꼬리 보정 |
| weight decay | **0** (백본 0.1) | **0** | decay 는 매 스텝, 갱신은 드물다 → 있으면 꼬리 행이 통째로 지워짐 |
| conv 초기화 | 0 | — | 학습 초기 identity 보존 |

**테이블은 잊지 않도록 설계돼 있다.**  이는 편집한 행이 자연 감쇠하지
않는다는 뜻이기도 하다.

### 3.4 Zipf 와 빈 행

n-gram 빈도는 Zipf 분포다.  소수 행은 수만 번 갱신되고 긴 꼬리는 몇 번뿐이다.
코퍼스에 한 번도 없던 열의 행은 (a) 초기화값 (b) 충돌 상대의 기울기만 갖는다.

> [실측] 픽셀플러스 코드(코퍼스에 없음)를 물으면 질문 형태마다 다른 여섯 자리를
> 지어내고, 5개 중 4개가 실존하지 않는 코드였다.  숫자 열 일반 행들이
> "여섯 자리 형식"은 주지만, 이 회사 고유의 행은 비어 있다.

> [실측] 행 노름: `the United States of America` 3gram_z +2.51,
> 조작한 `Alexander the Purple` −0.30.  자주 학습된 행은 노름이 크다.

## 4. 이것이 "지식"인 이유 — 그리고 아닌 이유

### 4.1 지식 벤치마크 증거

- [논문 §6.3] 추론 시 테이블 출력을 0 으로 막으면 사실 벤치마크가 원래의
  **29~44%** 만 남는다 (TriviaQA **29%**).  독해(C3)는 93% 유지.
  → "Engram 이 파라미터 지식의 주 저장소".
- [논문 §6.1] LogitLens: 테이블이 있으면 초기 층의 KL 이 훨씬 빨리 떨어진다.
  CKA: Engram-27B 의 5층이 MoE 기준선의 12층과 정렬.  테이블이 "초기 층의
  정적 패턴 재구성"을 대신해 실질 깊이를 늘린다.
- [Qwen Table 7] 없음 → layer 2: MMLU 62.78→64.71, CMMLU 68.10→72.48.
  [Table 9] 어휘를 키우면 **중국어(고유명사 많은 언어)만 일관 상승**.

### 4.2 지식의 실제 형태

"Alexander the Great was born in Pella" 는 테이블에 이렇게 있다:

```
행[the, Alexander]                  → "Great" 쪽
행[Great, the, Alexander]           → "was" 쪽
행[born, was, Great] · 행[born,was] → "in" 쪽
행[in, born, was]                   → "Pella" 쪽
```

**각 행은 자기 바로 다음 토큰 하나만 안다.**  문장은 행들이 이어받아 나온다.
"Alexander → Pella" 같은 장거리 연결은 테이블에 없다 — 그것은 어텐션이
앞의 토큰들을 보고 한다.  테이블이 하는 것은 "이 고유명사 열은 이렇게 이어진다"
를 매 위치에서 밀어주는 것이다.

### 4.3 테이블이 저장하지 않는 것

- **의미 키**: "픽셀플러스"라는 개체는 없다.  `셀 플러스 ␣` 라는 토큰 열만 있다.
  `Pixelplus`, `픽셀 플러스`, `픽셀플러스의` 는 각각 다른 행이다.
- **3 토큰 너머의 문맥**: `종목코드 픽셀플러스 ␣` 와 `픽셀플러스 종목코드는 ␣`
  는 마지막 3토큰이 달라 다른 행이다.  질문 형태가 바뀌면 진입 행이 바뀐다.
  단, 코드 내부 (`␣ 0 8`→`7` 이후)는 공유된다.
- **결정**: 행은 방향을 밀 뿐이다.  게이트(문맥 동의)와 백본(증폭)이 따라야
  토큰이 된다.  같은 크기의 편집이 어떤 자리에서는 통하고 어떤 자리에서는
  안 통하는 이유다.

## 5. 그러므로 "지식을 저장하는 법"은

사전학습이 하는 것과 같은 축에서, 한 문맥에 대해서만 하는 것이다.

1. 목표 토큰 열 `x_1 … x_n` 을 정한다 (예: 진입 프롬프트 + `087600`).
2. 위치마다 주소 16개를 계산한다 — 학습되지 않는 고정 해시라 서빙 중에도
   정확히 같은 행이다.
3. 그 행들을 움직여 `p(x_{t+1} | …)` 를 올린다.  사전학습은 이를 역전파로,
   우리는 역전파가 없는 W4A16 커널이라 SPSA(유한차분)로 한다.  목적은 같다.
4. 앞자리부터 순서대로 — 각 행은 자기 다음 토큰 하나만 담당하므로 자리 하나가
   행 세트 하나에 대응한다.  [실측] 5종목이 이 절차로 템플릿에서 6/6.
5. 사전학습과의 차이 하나: 사전학습은 그 행을 공유하는 **모든** 문맥의 합으로
   움직이고, 우리는 **하나**의 문맥으로 움직인다.  그 행이 다른 문맥에서 하던
   일은 무시된다.  부수 피해 측정이 필수인 이유다.  [실측] 헤드 선택으로
   영향 종목 431 → 1 로 줄일 수 있었다.
6. 다른 질문 형태에서도 나오게 하려면, 진입 행(첫 자리)은 형태마다 따로
   써야 한다.  코드 내부 자리는 공유된다.  전이 정도는 측정 중이다.
